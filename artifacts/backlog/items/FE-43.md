## What

Two guarantees, asserted where they can fail rather than configured and assumed.

1. **The tracked-file bytes CI builds, executes and mutates are the tracked-file bytes of the
   verified commit.** `* text=auto eol=lf` in `.gitattributes` stops the export transcribing them;
   `scripts/ci.mjs` compares every committed blob to the exported worktree before the image is built
   and refuses the run on any difference; the host's build-context digest travels as `CI_TREE_DIGEST`
   and `scripts/run-stages.mjs` recomputes it from the tree it is standing in before any stage runs.
2. **Every advertised mutation reaches and falsifies its intended gate.**
   `test/mutation-targets.test.mjs` proves each anchor resolves, and it runs inside `npm test`, which
   is a pipeline stage — so the reach of an opt-in suite is checked where that suite is not running.

## Why

The anchors were not loosened, and that was the whole decision. Teaching the two failing mutators to
accept `\r\n` would have turned the suite green in one line while leaving the artifact CI verifies
different from the commit it names — a check passing for a reason unrelated to the property it
exists to hold, which is this repository's subject. The tree was repaired instead, and the mutators
were left byte-literal so that they keep being the thing that notices.

## Notes

**Red before, green after.** Four falsifiers were written and run against `main` (5afcd00) before any
implementation. The two whose defects are real went red; the two whose defects were misdiagnosed in
[EP-12](EP-12.md)'s first draft went green and are recorded there rather than forced.

| falsifier | `main` 5afcd00 | this branch |
|---|---|---|
| exported tree is byte-identical to the commit | **RED** — 257 of 286 tracked files differ | GREEN — 0 differ |
| every advertised mutation reaches its gate | **RED** — 2 of 5 miss, in the exported tree | GREEN — 8 of 8 reach |
| the mutating stage runs on a disposable copy | GREEN | GREEN (unchanged) |
| `/repo` is not writable | GREEN — `EROFS` | GREEN (unchanged) |

The two red ones are one defect seen twice. `core.autocrlf` is `true` here and `.gitattributes`
pinned `eol=lf` for three globs only, so `git worktree add` — which is how `scripts/ci.mjs` produces
the build context — converted every other text file. The deltas are exactly the line counts, so it
is whole-file LF-to-CRLF and nothing else. The two mutators that failed are exactly the two whose
anchors carry a newline.

**Why it passed natively and failed in the container.** The developer checkout held LF for those two
files, having been written by tooling and never re-materialised by git; the container saw a pristine
export, which is the CRLF one. The native run was the anomaly.

**The new guarantees are themselves mutation-tested.** Three attacks were added to the suite, all
three land and all three are caught: commenting out the `eol=lf` attribute, replacing the export
comparison with an empty result, and aiming an existing mutation at a string its target does not
contain. The suite now advertises nine checks and reaches all nine.

**Deliberately not changed.** `scoreBasis`, any detector, any rule, any standard, FE-41 and FE-42.
The GitHub workflow calls `run-stages.mjs` directly with no host and no export boundary, so an absent
`CI_TREE_DIGEST` is not a failure there — refusing would fail a run for lacking a guarantee that does
not apply to it.
