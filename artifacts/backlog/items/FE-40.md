## What

`node scripts/ci.mjs` runs all eight checks in a disposable, network-less container; `node scripts/submit-pr.mjs` runs that gate and pushes only if the exact verified SHA is still HEAD. The stage list lives once, in `scripts/ci-stages.mjs`, and both the container and `.github/workflows/ci.yml` execute it through `scripts/run-stages.mjs`.

## Why

The eight gates were declared in a workflow file that has never run a job. Restating them per executor would have made the drift permanent, so the list moved out of the YAML and a test now fails if a gate command reappears there as its own step.

The five commits above are the branch in order; `7759969` is the `--no-ff` merge. `cc0a94c` fixes four findings an independent review raised against the boundary — an unrestricted `--out` that could have made the checkout writable by branch-controlled code, a mutation-check stage that could never pass against the read-only root, a UID mismatch that would have silently lost the receipt on a native Linux host, and a default-branch name containing a slash being truncated, which disabled the guard that refuses to submit the base branch onto itself. Each was reproduced before it was fixed.

`a23689c` is not part of the design. It is a latent defect the container surfaced on first contact: `npm test` quoted its glob, which stops the shell expanding it and hands the literal pattern to node, which only learned to expand it itself in v21 — so the test script could not run on the Node 20 the workflow pins. Nothing had ever noticed, because nothing had ever run it. The unquoted form is pinned by a test.

Verification is a file, not a claim: every run writes `artifacts/local-ci/latest.json` on failure as well as success, and it is deliberately not committed. The integrated merge commit was re-run through the same gate after landing and passed all eight stages.

What this does not establish is recorded in `docs/local-ci.md` and stated plainly: the hosted workflow is kept and refactored rather than deleted, it remains red, and that red is accurate external evidence of a billing block rather than a repository defect. Making it green would have meant suppressing a true report.
