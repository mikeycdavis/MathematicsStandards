## What

Stop counting the framework's own integrity rules inside an adopter's compliance score.

## Why

Four framework-integrity rules audit MathematicsStandards' own source documents and are scored against the adopting project.

## Notes

Single adopter, found by PvsNP. Shares a symptom with §0 — a passed row that does not say what it is a pass of — but needs a different fix.

Implemented on branch tier2-evidence-provenance, unmerged. Results carry `subject: project | run | framework`; framework- and run-subject rules leave the score denominator, and the render names them rather than dropping them silently. Guarantee C2 was stated as a cross-root pair in both directions before implementation, deliberately so that a changed path constant cannot satisfy it. The ownership question was then settled from the catalog rather than from convenience: `integrity.rule-lifecycle-honest` has no adopter-root reading to relocate to, and `integrity.provenance-digest` is asserted invariant across three adopter states — absent, drifted, correct — so an adopter can be neither punished nor flattered by a rule that is not theirs. Measured: RH `BLOCKED_BY_INVARIANT` 89 → 88 under a new score basis, PvsNP `NON_COMPLIANT` 97 unchanged.
