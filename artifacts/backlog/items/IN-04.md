## What

Make the checks this repository claims to run actually run somewhere, on evidence rather than on the presence of a configuration file.

## Why

The theme names the failure mode and this repository was committing it against itself. `.github/workflows/ci.yml` existed from EP-01 and read like a gate; no job it declared has ever executed. A framework whose subject is assurance that does not manufacture certainty cannot have its own build status be a badge for work nothing performed.

## Notes

Opened after the fact, on 2026-08-16, alongside EP-11 and FE-40. The initiative did not exist while the work it describes was being done — see FE-40 for why, and read the ordering as a record rather than a plan.

Distinct from IN-03 on purpose. IN-03 fixes what the field trials falsified in the framework's own rules; this initiative is about the repository's development machinery, which no adopter consumes. Parented to TH-01 rather than folded into a COMPLETE initiative, because attaching 2026-08-16 work under IN-01 would place a child after its parent's closure.

Left IN_PROGRESS. EP-11 closed what was asked for; the remainder is what this initiative still holds.

**The hosted workflow is demonstrated, non-authoritative, and intermittently unavailable.** It has executed the full pipeline on neutral hardware more than once — runs `31963761001` and `31963743124` on 2026-08-16, and run `32877711524` attempt 3 on 2026-08-26, which carried all eight stages and 250/250 tests green on the v3.0.0 release artifact `1faedcd`. So the capability is real and that half of the original blocker is closed.

It is **not** a gate, and its availability is not guaranteed. Hosted runs stop starting whenever the account's billing or spending limit lapses, and that condition has recurred repeatedly — including twice on 2026-08-26, once on either side of the release, the second time 23 minutes after a successful run. A non-start is recognisable and must not be read as a failure: zero steps, `runner_id` 0, no retrievable log, and the reason available only from the check-run annotation.

The durable position, unchanged by any of it: **local Docker CI is the required gate**, enforced on the exact SHA by `scripts/submit-pr.mjs` for the reason EP-11 gives. Hosted Actions is an independent second witness — preserved as evidence when it runs, investigated when it genuinely fails, and recorded but not waited on when it never starts.

**`artifacts/backlog/README.md:3` still tells the reader to "re-run the backlog script after changing anything in items/", and this repository contains no such script** — no `scripts/backlog.mjs`, no npm script matching it. Re-verified 2026-08-23. The tracker is generated, and generated correctly, but by a user-level skill that lives outside the repository; a contributor without that skill installed is told to run something that does not exist. Still unowned.

**A third remainder, opened 2026-08-23 as [EP-12](EP-12.md):** two of the six advertised mutation checks report `SETUP FAILED` inside the container and have never attacked their gate there. That one now has an owner and a measured cause.

**Recorded separately, and not work for this repository: merged-PR reconciliation cannot run here.** The `backlog-reconcile` skill matches merged pull requests by commit subject — `Merge pull request #N from …`, or a trailing `(#N)`. This repository merges `--no-ff` under subjects of its own ("Land the 2.0.0 release"), so none of its five merged PRs is discoverable, reconcile reports `Reconciling 82 items against 0 merged pull request(s)`, and two of its four checks report NOT RUN. The finding is real and worth knowing when reading a reconcile report — a reader skimming for failures would take the silence for an all-clear — but the defect is the skill's blind spot, not a property of this history. **Do not change the merge convention to be legible to it.** A commit subject exists to say what landed; bending it to match an external tool's regex would be the tail wagging the dog, and the convention is load-bearing here precisely because these merges are release events.
