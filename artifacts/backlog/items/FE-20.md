## What

lifecycle.failed-routes-preserved passes on a heading match while blind to the document the pointer names.

## Why

Replicated, and it passes in both projects for the wrong reason. PvsNP's FAILED_ATTEMPTS.md is 1,283 lines and append-only; RH's FAILED_APPROACHES.md is real; the ABANDONED path regex matches neither, and the rule passes on a ### heading in problem.md instead.

## Notes

This is the rule that forced the only duplication in RH's Standard 17 record. A framework that cannot read a project's strong native artifact will ask the project to restate it thinly — the exact corruption the governing question names.

Implemented on branch tier2-evidence-provenance, unmerged, and deliberately not repaired inside `lifecycle.failed-routes-preserved`: it is a reusable primitive, `resolveEvidencePointer`, in its own module. Guarantee C3 stated before implementation with the property that matters — a declared artifact is *read*, not merely counted, and one that does not resolve fails closed. Eleven pointer tests plus the escape-hatch pair, which was measured before it was closed: a fixture declaring an unresolvable artifact scored COMPLIANT / 100 and now scores NON_COMPLIANT / 97, so an unresolved declaration is worth exactly what a failure is worth and never more. Both adopters now discharge the duty through their own differently named artifacts.

The branch records one thing it did not take: an adopter's own `artifacts/provenance-digests.json` is still a declared artifact the framework never opens. That needs a new catalog rule rather than a different root for an existing one, and it is left to the same deferral discipline as §0j and §0k.
